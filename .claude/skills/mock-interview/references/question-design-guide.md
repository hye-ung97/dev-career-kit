# 질문 설계 가이드 (JD 5슬롯 파싱 + PSR 분해)

이 파일은 **1단계(면접 설계)**에서 읽는다. 목적은 하나다 — **질문이 "이력서를 낭독하게 만드는 질문"이 아니라 "그 회사가 실제로 궁금해할 지점"과 "지원자가 실제로 한 일"의 교집합을 정확히 겨누게** 하는 것.

질문 설계는 두 축으로 한다:
1. **JD 5슬롯 파싱** — 채용공고에서 "이 회사가 검증하고 싶은 것"을 5개 슬롯으로 구조화한다.
2. **PSR 분해** — 이력서의 한 줄을 문제·해결·결과로 쪼개 어디를 파고들지 앵커를 잡는다.

이 둘을 교차하면, 각 주제의 **첫 질문(오프너)과 꼬리물기 방향**이 자동으로 나온다.

> ⚠️ 이 설계는 **속으로만** 한다. 지원자에게 슬롯 표나 PSR 분해를 보여주지 않는다. 설계의 산출물은 "무엇을 어느 깊이로 물을지"에 대한 면접관 자신의 지도다.

---

## 1. JD 5슬롯 파싱

JD가 있으면 아래 5개 슬롯으로 쪼갠다. **JD가 없으면** 이력서의 지원 직무·경력에서 슬롯을 추론하고, `필수 기술`·`시니어리티`만 채운 채 진행한다.

| 슬롯 | 무엇을 뽑나 | 질문 설계에 쓰는 법 |
|------|------------|--------------------|
| **① 회사·도메인** | 어떤 서비스/도메인인가 (금융·커머스·인프라·데이터…) | 도메인 특유의 관심사를 질문에 심는다. 금융=정합성·멱등성·감사, 커머스=재고·동시성·정산, 트래픽=캐시·풀·확장 |
| **② 핵심 책임** | 이 사람이 매일 할 일 ("~를 설계·운영한다") | 이력서에서 이 책임을 **실제로 해본 근거**를 찾아 오프너로 삼는다. 없으면 가정 시나리오로 검증 |
| **③ 필수/우대 기술** | 반드시 쓰는 스택 + 있으면 좋은 스택 | 필수 기술 ∩ 이력서 기술 = **최우선 주제**. 우대 기술은 있으면 보너스 꼬리질문 |
| **④ 시니어리티** | 요구 연차·리드 여부 | 질문 깊이의 기준. 주니어=정의·적용, 미들=원리·트레이드오프, 시니어=설계 판단·장애 운영·의사결정 근거 |
| **⑤ 인재상·컬처** | 협업/오너십/성장에 대한 문구 | 클로징(2-C)의 컬처핏 질문을 이 슬롯에 맞춘다. "빠른 실행" 강조 회사면 오너십·의사결정 속도를 관찰 |

**교집합 규칙 (질문 우선순위의 뼈대):**
```
최우선   = ③필수기술 ∩ 이력서에서 본인이 주도한 경험     (그 회사가 궁금 + 검증 가능)
그다음   = ②핵심책임을 이력서 경험으로 방어할 수 있는가   (실무 시나리오로 확인)
보너스   = ①도메인 특유 관심사 + ③우대기술              (변별력용 심화)
컬처핏   = ⑤인재상 → 클로징 질문 축 선택
```

> **JD의 "우대사항"은 함정이자 기회다.** 우대 기술을 이력서에 적었다면 반드시 판다 — 진짜 쓴 건지, 이력서 채우기용인지 여기서 갈린다.

## 2. PSR 분해 (이력서 한 줄 → 질문 앵커)

이력서의 성과·프로젝트 문장을 **P(문제) · S(해결) · R(결과)** 세 조각으로 쪼갠다. 세 조각 각각이 **다른 종류의 꼬리질문**을 낳는다. 조각이 비어 있으면 **바로 그 빈칸이 첫 질문**이 된다.

| 조각 | 정의 | 이력서에 보통 어떻게 쓰였나 | 여기서 나오는 질문 |
|------|------|---------------------------|-------------------|
| **P (Problem)** | 어떤 문제/제약이 있었나 | 대개 **생략됨** ("~를 도입했다"만 있고 왜인지 없음) | "그걸 도입하기 전엔 뭐가 문제였죠? 안 하면 뭐가 터지나요?" → 문제 정의력 검증 |
| **S (Solution)** | 무엇을 어떻게 했나 | 가장 자세히 쓰여 있음 (기술명·방법) | "왜 그 방법이었나요? 대안은? 내부에서 어떻게 동작하죠?" → 기술 깊이·트레이드오프 |
| **R (Result)** | 결과가 어땠나 (숫자·영향) | "개선했다"처럼 **뭉뚱그려짐** | "몇에서 몇으로? 어떻게 측정했죠? 본인 기여는 어디까지?" → 경험 구체성 |

### 분해 → 질문 매핑 예시

이력서 문장:
> "Redis 캐싱을 도입해 상품 조회 API 응답 속도를 개선했습니다."

PSR 분해:
- **P**: (빈칸) — 왜 느렸는지, 무엇이 병목이었는지 안 쓰여 있음
- **S**: Redis 캐싱 도입 — *어떤 데이터를, 어떤 전략(cache-aside?), 왜 로컬캐시가 아니라 Redis인지* 안 쓰여 있음
- **R**: "개선" — *수치 없음*

→ 설계된 질문 흐름:
```
오프너(P 빈칸)   "캐싱을 넣기 전, 그 조회는 왜 느렸나요? 병목이 어디였죠?"
S 파고들기        "왜 로컬 캐시가 아니라 Redis였나요? 네트워크 홉이 하나 느는데요."
S 내부기작        "어떤 자료구조로 담으셨어요? Redis가 그 조회를 빠르게 만드는 이유는요?"
R 정량화          "'개선'을 숫자로 하면요? p99 기준 몇에서 몇으로, 어떻게 측정했죠?"
R 기여 구분        "그 작업, 본인이 어디까지 하셨어요? 팀이 한 건 뭐고요?"
```

> **핵심: P와 R의 빈칸이 가장 좋은 오프너다.** 지원자가 이력서에 안 쓴 조각을 물으면, 준비된 대본이 아니라 실제 이해가 드러난다. S는 이미 자세히 준비돼 있으므로, S는 "왜/내부기작/대안"으로 한 겹 더 벗겨야 변별이 된다.

### PSR로 "지어낸 성과" 걸러내기
- R의 숫자를 캐물었을 때 **측정 방법을 못 대거나**, P(문제)를 물었을 때 **왜 그게 문제였는지 설명 못 하면** → 남의 성과를 옮겨 적었을 신호. 압박 모드 꼬리물기의 `실제 vs 가정 구분 요구`·`정량·측정 검증` 기법으로 확인한다.

## 3. 설계 산출물 (속으로 만드는 주제 지도)

각 주제마다 아래를 속으로 정리하고 2단계 진행에 쓴다. **지원자에게 보여주지 않는다.**

```
주제: {예: Redis 캐싱}
- JD 근거: ③필수기술(Redis) ∩ 이력서 주도경험  → 최우선 주제
- PSR 빈칸: P(왜 느렸나) 없음, R(수치) 없음     → 여기부터 연다
- 오프너: "캐싱 전엔 그 조회가 왜 느렸죠?"
- 꼬리 방향: S(왜 Redis)→내부기작(자료구조)→TO(무효화)→장애(stampede)→R(수치·기여)
- 목표 깊이: 미들(④시니어리티) → 7~9단계, 내부기작·트레이드오프까지
```

이 지도는 **계획일 뿐**이다. 실제 꼬리질문은 지원자의 답변에서 실시간으로 만든다 (SKILL.md의 압박 모드 규칙). JD 슬롯과 PSR은 "어디를 겨눌지"를 주고, 답변이 "어떻게 팔지"를 준다.
