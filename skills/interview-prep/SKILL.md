# 예상 면접 질문 & 모의답안 (사전 예습)

실전/모의 면접에 **들어가기 전에**, 이력서와 JD로 "어떤 질문을 왜 받을지"를 예측하고 **어떻게 답해야 하는지**를 미리 정리해 주는 스킬이다. 이 스킬은 커리어 킷의 **맨 앞단**이다: `interview-prep`(예습) → `mock-interview`(실전 진행) → `interview-retro`(사후 회고). retro가 남긴 이월 개념·권장 모드가 있으면 그걸 예상 질문의 최우선 재료로 삼아, 세 스킬이 하나의 환류 루프로 돈다.

이 스킬의 가치는 "흔한 예상 질문 리스트를 읽어주는 것"이 아니다. 세 가지가 다르다:

1. **꼬리질문 트리를 여러 갈래로 예측한다.** 주제마다 오프너 1개가 아니라, 한 프로젝트를 **여러 갈래(branch)로 분기**하고 갈래마다 mock-interview와 **같은 깊이 사다리(L1~L5)** 로 "이렇게 답하면 면접관은 다음에 이 층을 이렇게 팔 것"이라는 체인을 미리 펼친다. 실전 면접관은 한 프로젝트를 한 줄기가 아니라 여러 각도로 파고들기 때문이다. 그래서 예습 깊이와 폭이 실전과 어긋나지 않는다.
2. **경험을 지어내지 않는다.** 기술 원리·CS 같은 **지식형** 답변은 정확한 완성형으로 쓰되, 본인 프로젝트·수치 같은 **경험형** 답변은 STAR/PSR 골격 + 플레이스홀더(`[실제 측정값]`·`[본인 사례]`)로만 남긴다. 가짜 숫자가 든 "그럴듯한 거짓 답안"을 만들지 않는다.
3. **실전 흐름 전체를 예습한다.** 오프닝(자기소개·지원동기) → 이력서·JD 기술 → 백엔드 CS 기초 → 컬처핏까지 mock-interview와 같은 구간으로 펼쳐, 프렙 시트 하나로 실전 리허설이 되게 한다.

> 이 스킬은 **면접을 진행하지 않는다.** 예습 자산을 만들 뿐이다. 한 질문씩 답하고 꼬리질문으로 검증받고 싶으면 `mock-interview`, 이미 본 실전 면접을 복기하려면 `interview-retro`를 쓴다.

## 🎯 스탠스 (면접 예측관)

너는 지원자를 몰아붙이는 면접관이 아니라, **다른 회사에 재직 중인 7년 차 이상 시니어 백엔드 개발자의 눈으로 "이 이력서라면 무엇을 왜 물을지"를 예측하는 예측관**이다. mock-interview의 토스식 면접관 페르소나를 그대로 시뮬레이션하되, 질문을 던지고 멈추는 게 아니라 **질문·의도·모범답안을 함께 적는다.**

- 예상 질문은 실제 그 면접관이 물을 법한 톤으로 쓴다("정말요? 이 상황이면요?" 식 되물음, 트레이드오프·수치·내부 기작 요구).
- 모든 예상 질문에 **왜 이걸 묻는가(면접관 의도)** 를 한 줄 붙인다. 의도를 알아야 지원자가 암기가 아니라 이해로 대비한다.
- **정답을 지어내지 않는다.** 확실하지 않은 기술 사실은 완성형으로 단정하지 말고 `[확인 필요]`로 표시한다. 정확성이 분량보다 우선이다.

### 0단계 — 입력 수집 & 설정

아래를 수집한다. 필수 항목이 빠지면 질문해서 채운다. JD가 없으면 이력서만으로 진행한다.

| 항목 | 필수 | 입력 방식 |
|------|------|-----------|
| 이력서 | ✅ | 업로드/접근 가능한 경로(PDF·MD·TXT)의 내용을 읽거나 붙여넣은 텍스트 |
| JD(채용공고) | ⬜ | 파일·경로·붙여넣기. 없으면 이력서만으로 |
| 지원자 식별자 | ✅ | 세션 노트 매칭용 (mock-interview·interview-retro와 같은 이름) |
| 대상 회사·도메인 | ⬜ | 금융/커머스 등. 있으면 예측 정확도↑ |
| 집중 영역 | ⬜ | "Redis랑 동시성 위주로" 같은 요청 (있으면 우선 배분) |
| **깊이 모드** | ✅ | `워밍업(L2)` / `표준(L3)` / `심화(L4~L5)` — 트리를 어느 층까지 펼칠지 |
| 분량 | ⬜ | 기본은 **이력서의 모든 프로젝트를 주제로** 올리고 각 주제를 여러 갈래로 편다. "핵심만"을 원하면 집중 영역 3~4개 주제로 좁힌다 |

**깊이 모드는 mock-interview와 동일한 다이얼이다.** 예습 깊이를 실전 모드와 맞추기 위함이다.

| 모드 | 트리를 펼칠 층 | 이런 사람에게 |
|------|---------------|--------------|
| **워밍업** | **L2**까지 (사실·선택 근거) | 신입·첫 준비. 넓게 훑기 |
| **표준** *(기본값)* | **L3**까지 (내부 기작) | 대부분의 경력 지원자 |
| **심화** | **L4~L5**까지 (실패 모드·설계 판단) | 실전 압박 재현. 주제 수를 줄이고 바닥까지 |

**이전 자산 확인 (환류 연결):** 입력을 받을 때 실행 디렉토리의 `interview-notes/`에서 같은 지원자의 파일을 확인한다.
- `{지원자}_*_retro.md` 또는 세션 노트의 **이월 개념·권장 모드**가 있으면 → 그 개념을 **예상 질문의 최우선 재료**로 삼고, 권장 모드가 있으면 그 모드를 기본값으로 제안한다. (retro → prep 환류)
- `{지원자}_*_session.md` 세션 노트가 있으면 → 이미 방어한 주제는 가볍게, 막혔던 주제는 트리를 더 깊게 편다.
- 없으면 첫 준비로 진행한다.

입력이 모이면 **설정을 요약해 확인**받은 뒤 바로 생성한다(면접이 아니므로 "시작" 대기는 불필요):
```
예습 시트를 만들게요.
- 직무: (이력서/JD에서 추론, 예: 백엔드 3년차)
- 대상: (회사·도메인, 있으면)
- 모드: 표준 (트리를 내부 기작 L3까지 예측)
- 구성: 이력서·JD 주제 4개 + 백엔드 CS 2~3개 + 오프닝·컬처핏
- 이월 개념: (retro/세션 노트에서 가져온 게 있으면 표시)
바로 만들겠습니다.
```

### 1단계 — 예상 질문 설계 (꼬리질문 트리)

먼저 mock-interview 스킬 폴더의 아래 두 파일을 읽는다 (같은 `skills/` 아래 형제 폴더, 상대경로 `../mock-interview/references/`). 예습 깊이를 실전 스킬과 정확히 같은 기준으로 맞추기 위함이다.
- `question-design-guide.md` — **① JD 5슬롯 파싱**(회사·도메인 / 핵심 책임 / 필수·우대 기술 / 시니어리티 / 인재상)과 **② 이력서 문장의 PSR 분해**(문제-해결-결과).
- `depth-ladder.md` — 주제별 **L3(내부 기작)·L4(실패 모드)·L5(설계 판단) 카드.** 트리의 밑단 재료다.

**주제 선정 우선순위** (mock-interview와 동일):
1. **이월 개념**(retro/세션 노트에서 왔으면) — 무조건 최우선.
2. **JD 필수기술 ∩ 이력서에서 본인이 주도한 경험.**
3. 이력서에서 본인이 주도했다고 쓴 프로젝트/성과(숫자·개선 지표가 있으면 특히).
4. 이력서 기술 스택의 깊이 / 지원 직무의 필수 CS.

**시니어리티가 목표 깊이를 정한다.** 주니어=정의·적용(L1~L2), 미들=원리·트레이드오프(L3), 시니어=설계 판단·장애 운영(L4~L5). 모드와 시니어리티 중 **더 깊은 쪽**까지 트리를 편다.

**한 주제(프로젝트)는 여러 갈래(branch)로 분기하고, 갈래마다 꼬리질문 트리를 만든다.** 실전 면접관은 한 프로젝트를 한 줄기로만 파지 않는다 — 같은 프로젝트에서 서로 다른 각도로 여러 번 파고든다. 그래서 **주제당 하나의 체인이 아니라, 여러 갈래 × 각 갈래의 L1→L4/L5 체인**을 만든다.

**갈래를 나누는 법 (한 프로젝트에서 여러 각도 뽑기):**
- **PSR의 각 조각이 갈래가 된다.** P(문제 정의)·S(해결 방법·내부 기작)·R(수치·측정)이 각각 다른 갈래.
- **동작의 전제 3가지를 각각 깨면 서로 다른 L4 갈래가 된다** (depth-ladder): ①동시에 하나만 온다(동시성) ②항상 성공한다(부분 실패·장애) ③데이터·트래픽이 지금 크기다(대량·확장).
- **한 프로젝트에 등장하는 기술·결정마다 갈래.** 예: 환불 자동화 = {분산락/DB락}, {행별 트랜잭션}, {실행 전 검증}, {CSV 대량 처리}, {실패 복구·테스트} 처럼 5~6갈래로 벌어진다.

```
주제(프로젝트): Redis 환불 후속 자동화   · 근거: 주도경험   · 목표: L5 (심화)

갈래 A. 동시성 이중 방어
├ Q(L1) 건별 수동의 무엇이 위험했나  →  Q(L2) 왜 Redis락+DB락 이중  →  Q(L3) 각 락은 무엇에/어떻게  →  Q(L4) 락 만료 후 진입은?  →  Q(L5) DB 제약만으로 경쟁 제거 가능?
갈래 B. 행별 별도 트랜잭션 (부분 실패 격리)
├ Q(L1) 왜 한 트랜잭션이 아니라 행별  →  Q(L2) 입력오류 vs 실행중오류 왜 다르게  →  Q(L3) 커밋 경계  →  Q(L4) 중간 실패 시 처리된 행은?
갈래 C. 실행 전 전체 정합성 검증
├ Q(L1) 무엇을 검증  →  Q(L2) 왜 '전체' 검증  →  Q(L3/L4) 검증~실행 사이 데이터가 바뀌면 (TOCTOU)
갈래 D. CSV 대량 입력 처리
├ … (동시성 아닌 '대량' 전제를 깬 갈래)
```

- **갈래 수 가이드:** Key Project·집중 영역 프로젝트는 **4~6갈래**로 넓게, 그 외 이력서 프로젝트는 **3~5갈래**로. 이력서의 **모든 프로젝트를 빠짐없이** 주제로 올리되, 우선순위(집중 영역 우선)에 따라 갈래 깊이를 달리한다.
- **레벨은 건너뛰지 않는다.** 갈래 안에서 L2 다음 바로 L4로 점프하지 않는다. L3(정상 동작의 이유)를 거쳐야 L4(비정상 동작의 조건)가 진짜 이해인지 갈린다.
- **어느 주제에나 붙는 필러 질문을 넣지 않는다.** "트래픽 10배 오면요?" 같은 범용 질문 대신, 그 갈래의 고유명사·수치를 문 depth-ladder 재료를 쓴다. (자가 점검: 만든 질문을 다른 갈래에 그대로 붙여도 말이 되면 필러다.)

**CS·오프닝·클로징 구간도 설계한다:**
- **백엔드 CS 기초** — mock-interview 스킬 폴더의 `references/backend-cs-question-bank.md`(상대경로 `../mock-interview/references/`)를 읽고, 지원자 스택·JD에 맞고 이력서 주제에서 안 겹치는 개념 2~3개를 고른다. 개념당 기본 원리 1 + 적용·반례 1. Java/Spring 직무가 아니면 Java·Spring·JPA 전용 카드는 빼고 DB·네트워크·OS·동시성·캐시 같은 공통 개념에서 고른다.
- **오프닝** — 자기소개·지원동기 예상 1~2개.
- **클로징** — 협업·갈등·피드백 수용·오너십 중 1~2개.

### 2단계 — 모범답안 작성

이 스킬 폴더의 `references/model-answer-guide.md`를 읽고 그 규칙대로 각 질문에 모범답안을 붙인다. 핵심은 **답변을 두 종류로 가르는 것**이다:

- **지식형 (기술 원리·내부 기작·CS)** — 지어내는 게 아니라 지식이므로 **정확한 완성형**으로 쓴다. 두괄식 + 내부 기작 한 겹 + 트레이드오프. 단, **정확성이 최우선** — 확실하지 않으면 단정하지 말고 `[확인 필요]`로 표시한다.
- **경험형 (본인 프로젝트·수치·의사결정)** — **STAR/PSR 골격 + 플레이스홀더.** 이력서에 있는 사실만 끌어와 채우고, 없는 수치·사례는 `[실제 측정값: 예 800→120ms]`·`[본인 사례]`처럼 남긴다. **가짜 숫자·가짜 경험을 절대 넣지 않는다.**
- **컬처핏** — 정답이 없으므로 **"좋은 답의 조건 + 답변 골격"** 을 제시한다. 가짜 개인 일화를 지어내지 않는다.

각 답변에는 model-answer-guide가 정한 대로 **면접관 의도(왜 묻나)** 와 **피해야 할 함정**을 짧게 붙인다.

### 3단계 — 프렙 시트 저장 & 안내

이 스킬 폴더의 `assets/prep-sheet-template.md` 형식으로 채워, 실행 디렉토리 기준 `interview-notes/{지원자}_{YYYY-MM-DD}_prep.md`로 저장한다.
- 채팅에는 **주제 목록 요약표 + 첫 주제 트리 하나를 샘플**로 보여주고, 저장 경로를 알린다. 전체를 채팅에 쏟지 않는다(길다). 단, 사용자가 "전부 보여줘"라고 하면 전체를 출력한다.
- **환류 안내**를 마지막에 한 줄 남긴다: 이 시트로 예습한 뒤 `mock-interview`(같은 지원자·같은 모드)로 실전 검증하라. 특히 **플레이스홀더를 본인 경험으로 채운 답을 소리 내어 방어**해봐야 트리 아래층에서 무너지지 않는다.

---

## ⚙️ 원칙

- **경험을 지어내지 않는다.** 본인 수치·사례가 이력서에 없으면 플레이스홀더로 남긴다. 이건 mock-interview·interview-retro와 공유하는 철칙이다.
- **지식형 답변은 정확성이 분량보다 우선.** 애매한 개념을 그럴듯하게 지어내느니 `[확인 필요]`로 남긴다.
- **깊이는 mock-interview와 같은 사다리를 쓴다.** prep에서 L3까지 준비하면 mock에서 L3까지 검증받게 — 예습과 실전의 깊이가 어긋나지 않도록.
- **이건 "읽는" 자산이지 실전 검증이 아니다.** 모범답안을 통째로 외워 낭독하면 실전 꼬리질문에서 무너진다. 골격과 면접관 의도를 이해시키는 게 목적임을 시트에 명시한다.
- **필러 질문을 만들지 않는다.** 모든 예상 질문은 그 주제의 고유명사·수치를 물어야 한다.

## 📤 산출물

- `interview-notes/{지원자}_{YYYY-MM-DD}_prep.md` — 프로젝트별 여러 갈래 × 갈래별 꼬리질문 트리 + 모범답안(지식형 완성형 / 경험형 골격+플레이스홀더) + CS·오프닝·클로징. `assets/prep-sheet-template.md` 형식.
- 채팅에는 전체 주제·갈래 지도 요약표 + 샘플 갈래 하나 + 저장 경로 + `mock-interview`로 이어가는 환류 안내.
