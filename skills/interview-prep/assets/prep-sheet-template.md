# 🎯 면접 예습 시트 (예상 질문 + 모의답안)

> **이건 대본이 아니라 골격이다.** 모범답안을 통째로 외워 낭독하면 실전 꼬리질문에서 무너진다. 각 답의 **면접관 의도**와 **내부 기작**을 이해하고 **본인 말로** 재구성하라. `[대괄호]` 플레이스홀더는 **반드시 본인 실제 경험·수치로** 채워야 한다 — 지어낸 값을 외우면 "어떻게 측정했나요?" 한 번에 무너진다.
>
> **저장 위치·이름:** 실행 디렉토리 기준 `interview-notes/{지원자}_{YYYY-MM-DD}_prep.md`.
> `{ }`는 실제 내용으로 채운다.

## 2) 이력서·JD 기술 주제 (핵심) — 프로젝트별 여러 갈래 × 갈래별 트리

> **한 프로젝트는 여러 갈래(branch)로 갈라진다.** 실전 면접관은 한 프로젝트를 한 줄기가 아니라 여러 각도로 판다. 갈래는 트리거(수치 주장·결여·본인 용어·"보장" 문장·장애 서사), PSR 조각(P·S·R), 동작의 전제(동시성·부분 실패·대량·응답 유실·단계 사이 실패·신뢰 경계)를 깨는 방향에서 나온다. 갈래마다 **사실·경계 질문으로 시작**하는 L1→L4/L5 체인 + 모범답안·의도·함정. 각 질문 옆 `[단계]`는 `toss-patterns.md` §3의 꼬리질문 단계다.
>
> *(각 질문의 `[단계]`는 토스 계열 면접 기록에서 관찰된 경향에 따른 것이지, 반드시 나오는 질문이 아니다.)*

### 주제 1 — {Redis 환불 후속 자동화}   · 근거: {주도경험}   · 목표: {L5 (심화)}   · 갈래: {A~F}
- **프로젝트 공통 대비**: 기여 범위 `[본인 몫: 설계/구현/운영 중]` · 조건 강화 {예: "서버가 두 대로 늘면요?"} · 사용자 영향 {예: "중간에 실패하면 고객은 무엇을 보나요?"}

#### 갈래 1-A. {동시성 이중 방어 (분산락 + DB락)}   · 트리거: {"보장" 문장 — "중복 실행 방지"}
```
{L1 사실·경계: 락은 어디에·TTL은 얼마 → L2 왜 이중 방어 / 대안: DB 제약만 → L4 락 만료 후 진입 → L3 그때 DB 락은 무엇에 걸리나 → L4 2단 실패 → L5 단순화: DB 제약만으로 경쟁 제거?}
```
*(위 체인은 경로 B(상황 먼저) 예시다. 아래 목록은 L 순으로 정리한다.)*
- **L1 [사실·경계 고정] — {질문}?** ({경험형}) "{결론부터 이분법 + `[실제 설정값]`}" · 의도: {…} · 함정: {흐린 답}

- **L4 [실패] — {질문}?** ({지식형+경험형}) "{`[현재 구현]` / `[개선 아이디어]` 분리}" · 의도: {…} · 함정: {현재와 개선을 섞기}  *(심화 — 표준은 경로 B일 때 L3 진입용으로만)*
